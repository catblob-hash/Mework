`preview_find_logs` finds the log lines that say what a plain-language `query` asks about, across the conversation's preview page console and a dev server's output, without the model reading either log: both are cut into their output rounds — console entries and reads of the server's output — the TypeSafe Jev decision model scores each against the query, and every one that clears the call's `threshold` comes back whole, labelled `console entry N` or `server` with its numbered lines. The model reaches for it when it is after one thing — a hydration warning, the error behind a failed request, the line where a rebuild broke — in logs too long to page through with `preview_console_logs` and `preview_logs`.

## Approval

Classified as a sensitive browser observation (`browser.sensitive_observation`, high risk, unbounded effect), because console and server log lines can carry tokens and error context; the card says so. Manual, Accept edits and Plan mode ask; Full access does not. The classification ignores `source`, so a call limited to the server's output asks as well, although `preview_logs` reads the same buffer without a card. A call without `query` is refused before any card is raised. This is not one of the page tools, so **Always allow** is offered and remembers it for this tool in this conversation until the app restarts, and the takeover card a page tool raises on a page you signed into yourself does not come up for it. Sending the lines to TypeSafe is not a separate approval: enabling the tool and saving the key is the opt-in.

## Behavior and limits

The call needs what `preview_console_logs` needs — a dev server this conversation may address, or a page the pane already holds — and fails without one. The TypeSafe key is read next, before either log: a missing one fails the call with a message pointing to the key setting. `query` is trimmed and capped at 2,000 characters; `threshold` must lie between 0 and 1 and is rounded to three decimals; `source` is `all` (the default), `console` or `server`, and anything else is refused.

The console part is every entry the page holds for its current document — at most 200, each as `[level] text` — with no level filter and no tail slice. The server part is that server's whole buffer, up to 1,000 reads from its pipes, both streams in arrival order, split into lines, ANSI colour escapes included. `serverId` chooses the server; without it the call takes the first starting or running server this conversation may address, as `preview_logs` does, and an id it cannot address fails the call with a pointer to `preview_list`. It never changes which console is read: the conversation has one preview page. A server on an SSH machine is read from the same buffer, which its output reaches over the machine's link. With `all` and no server running, the console is scored alone and the answer says so; with `server` and none running, the call fails and suggests `preview_start` or `source: "console"`. A server's buffer is gone once it exits or is stopped.

Each log is cut into its own output rounds, the blocks this tool scores and returns. The console is cut by entry: one console message is one entry, however many lines it spans — an error stays with its stack. The server log is cut by read: each read from its pipes is the output of one write, as a rule, or of several that arrived together; a read that stops mid-line is joined to the next one, which finishes the line, and a read with nothing but blank lines is not scored. Every block is scored on its own, with a question of its own, and several share one request: as many as the request budget holds — 1,500 characters for short material, then whatever keeps the call near 150 requests, up to 12,000 — and never more than 32. Requests run eight at a time, and every TypeSafe request Mework makes shares one pace — 32 at once after a quiet spell, then 18 a second, under TypeSafe's 1,200 a minute — so a long log takes longer rather than coming back partly unscored. A block longer than 12,000 characters is scored in parts — along its lines, and a longer line in slices — and scores what its best part scores; it still comes back whole, its header naming the lines of the best part. No part of either log, oldest or newest, is left out to keep the count down.

The answer opens with `Scored N console entries and M server lines.` — what was gathered. A count follows, such as `2 hits at or above 0.600 for query "…" (57 blocks of logs scored, 3 requests).`, then every block that cleared, highest score first with console and server interleaved: `--- console entry 7 (score 0.833) ---` followed by the entry as the console holds it, or `--- server lines 41-43 (score 0.833) ---` followed by the read, each line with its number in that log, `cat -n` style. Console entries are numbered in the order this call gathered them, and server lines count lines of that one log as gathered; neither `preview_logs` nor `preview_console_logs` numbers its output, so a number places a hit rather than addressing it. Scores carry the threshold's three decimals, so a reported score can be passed back as a threshold. When nothing clears, the answer says so and names up to three best-scoring blocks with their scores. When both logs are empty it answers `There are no console or server log lines to score.` without a request. Output over 64 KiB is truncated.

Answers of `429` and `529` are retried twice, after 1 s and 2 s or the server's `Retry-After` up to 10 s, and each attempt has 30 s. A request that still fails leaves its blocks unscored, and the answer counts the failed requests and the blocks they left unscored; the call fails only when nothing at all was scored. A key TypeSafe rejects fails the call with a message pointing to the key setting. Stopping the run returns at once with `nothing was returned`; requests already in flight finish on their own.

The console is read under `preview_console_logs`'s name and bounded at 30 seconds: a sleeping page is woken for it, and a crashed one is reset to a blank document first, without the note `preview_console_logs` adds. A dialog or file chooser the page is holding, or a page you have taken over and not handed back, refuses the read with a message that names `preview_console_logs`. Scoring starts only after the read, outside the page's automation lock, so the page is not held while TypeSafe answers, and no 30-second clock covers the call as a whole.

## The decision model

`preview_find_logs` has no row of its own: it is the decision-model form of `preview_logs`, chosen under the **Server logs** row on the **Dev servers** page of the conversation's preview tool window. **Add decision-model parameters** enables `preview_logs` and `preview_find_logs` together; **Decision model only** enables `preview_find_logs` alone, and the raw server log with its level and text filters is no longer offered. Once a run has handed the model either tool, the window will not switch the row off or offer a form that drops it. Seeded presets leave it off, because it cannot run until TypeSafe's key is saved under Global settings → Decision model providers, which keeps it in the operating system's credential store. Each request sends TypeSafe's API the query and, for each of its blocks, the label — `console entry N`, or `server` and its line range — and the text; with `source: "console"` no server output leaves the machine, and with `"server"` no console text does. A score is Jev's probability-weighted answer on four levels — unrelated, loosely related, relevant (contains part of what was asked), direct hit — mapped onto 0 to 1, so the levels sit at 0, 0.333, 0.667 and 1.
