`find_content` finds where one text file contains what a plain-language query describes, without the model reading the file: the file is cut into its own blocks — functions and other symbols, sections, paragraphs — the TypeSafe Jev decision model scores each against the query, and every block that clears the call's `threshold` comes back whole, under its line range, each line numbered. The model reaches for it on a file too long to read whole — a large module, a log, a generated spec — when it knows what it is after but not the words it is spelled in, which is where `grep` falls short. A hit's line numbers go straight into `read` or `edit`.

## Approval

Calls are classified as reads, judged by the same path rules as `read`. A file inside the workspace, the app-data directory or an extra working directory granted to the conversation is scored without asking at every security level, Plan mode included. A file outside those roots asks under `request_approval` and Plan mode and passes under `allow_edits` and `full_access`; **Always allow** can remember that for this tool in this conversation, capped at the risk level of the card you answered. `memory/` under the app-data directory is refused at every level, `full_access` included. Sending the blocks to TypeSafe is not a separate approval: enabling the tool and saving the key is the opt-in.

## Behavior and limits

The target must be a regular UTF-8 text file of at most 2 MiB. An image — a PNG, JPEG, GIF or WebP signature — is refused as `<path> is an image; only text files can be scored`, and an empty file answers `<path> is empty; there is nothing to score.` without a request. `start_line` (default 1) and `end_line` (inclusive, default the last line) pick the range; unlike `read` there is no line cap, an `end_line` past the end is clamped, and a `start_line` past it is an error. `query` is trimmed and capped at 2,000 characters; `threshold` must lie between 0 and 1 and is rounded to three decimals.

The range is cut into its original blocks — the innermost units the file is made of — and a block is what gets scored and what comes back, always whole. When a language server claims the file, the blocks are its innermost document symbols: a function, method or other symbol with no symbols inside it, together with the comment and attribute lines directly above it at its indentation. A container such as an `impl` or a class is not a block itself: its members are, and its own header and closing lines are blocks of their own. The server has to be one Mework may start without asking — a built-in preset or one from your own `~/.mework/lsp.json` — or, when the workspace's own `.mework/lsp.json` names it, one an approved `lsp` call has already started; its answer is awaited for 5 seconds, and a cold server that needs longer goes on starting for the next call. A Markdown file is cut into sections, each heading with everything up to the next heading of any level. Anything else — the lines between symbols, a file no server answers for in time, a file on a WSL or SSH machine — is cut by indentation: a block is a line with the more deeply indented lines under it and its closing `}`, `)`, `]`, `end` or `fi`, with the comments and attributes directly above it; a run of one-line blocks between blank lines is one paragraph while it is at most 1,500 characters — prose, a run of imports — and a block per line past that, as data; and a block over 12,000 characters that holds two or more blocks with bodies is taken for a container and opened into its head, its members and its closing line. Blank lines between blocks are not scored. Every block is scored on its own, with a question of its own, and several share one request: as many as the request budget holds — 1,500 characters for short material, then whatever keeps the call near 150 requests, up to 12,000 — and never more than 32. Requests run eight at a time, and every TypeSafe request Mework makes shares one pace — 32 at once after a quiet spell, then 18 a second, under TypeSafe's 1,200 a minute — so long material takes longer rather than coming back partly unscored. A block longer than 12,000 characters is scored in parts — along its lines, and a longer line in slices — and scores what its best part scores; it still comes back whole, its header naming the lines of the best part.

The answer opens with a count — `1 hit at or above 0.600 for query "…" (40 blocks of src/auth.rs scored, 3 requests).` — then every block that cleared, highest score first, as `--- src/auth.rs lines 29-47 (score 1.000) ---` followed by the whole block, each line prefixed with its number in the file, right-aligned in six columns and then a tab, as `cat -n` prints it. The numbers are for the reader; the decision model is never shown them. Paths are relative to the workspace. Scores carry the threshold's three decimals, so a reported score can be passed back as a threshold. When nothing clears, the answer says so and names the three best blocks with their scores; when requests fail, it counts them and the blocks they left unscored. A hit is not a read: `edit` and `write` still want the file `read` first. Output over 64 KiB is truncated, so a very long block can come back cut short.

Answers of `429` and `529` are retried twice, after 1 s and 2 s or the server's `Retry-After` up to 10 s, and each attempt has 30 s. A request that still fails leaves its blocks unscored, and the answer counts the failed requests and the blocks they left unscored; the call fails only when nothing at all was scored. A missing key, or one TypeSafe rejects, fails the call with a message pointing to the key setting. Stopping the run returns at once with `nothing was returned`; requests already in flight finish on their own. On a WSL or SSH workspace the file is read on that machine and its text comes back to be scored under the same limits.

## The decision model

`find_content` is its own row under **Files and search** in the tool picker, marked **Decision model**, not in the **File tools** window behind the `files` row. Seeded presets leave it off, because it cannot run until TypeSafe's key is saved under Global settings → Decision model providers, which keeps it in the operating system's credential store. Each request sends TypeSafe's API the query and, for each of its blocks, the block's label — its workspace-relative path and line range — and its text; only the scored range leaves the machine. A score is Jev's probability-weighted answer on four levels — unrelated, loosely related, relevant (contains part of what was asked), direct hit — mapped onto 0 to 1, so the levels sit at 0, 0.333, 0.667 and 1. Subagents are not barred from it.
