# 使用 Mework

本页按你每天实际接触它们的顺序，介绍应用的各个部分。这里说明当前版本的行为；如有刻意设置的限制，也会明确指出。

## 工作区与对话

**工作区**是磁盘上的一个文件夹。文件工具受其边界约束，Shell 从其中启动，项目记忆和项目说明从其 `.mework/` 目录读取，并会发现其中的 `hooks.json`、`mcp.json`、`lsp.json`、`skills/` 与 `tool-descriptions/`。在侧边栏中通过**添加工作区**添加（会打开原生文件夹选择器；宿主仅信任你通过此方式选择的文件夹）。没有文件夹的工作区是应用数据目录下的临时暂存区域。

**对话**（侧边栏中称为“任务”）属于某个工作区，并有自己的设置、历史记录和后台任务。创建方式有三种：

- 工作区行上的 **+** 按以下顺序使用：该工作区的默认预设、工作区上一次对话的设置、全局默认预设。
- 侧边栏顶部的**新建任务**、`Ctrl+N` 和空状态按钮始终使用全局默认预设。
- **从此消息分支**，位于任意用户消息的工具栏上，会把这条消息之前的历史复制到一个嵌套在本对话之下的新对话中，并把这条消息作为草稿交给新的输入框。

对话历史可编辑：你可以插入或编辑用户消息和模型回复、删除上下文，以及创建分支。编辑会持久化到宿主，下一次请求会从持久化的历史记录重新构建，绝不会依据渲染器当前碰巧显示的内容。

## 预设与对话设置

**预设**是一份对话设置的可复用副本（对话设置 → **对话预设**）。套用预设会把它的字段复制进对话，之后两者互不相干：编辑预设绝不会更改已有对话，编辑对话也绝不会回写预设。**另存为预设**把当前对话的设置以一个新名字保存下来；预设的开局消息写在预设自己的**对话模板**页上，而不是从对话中截取。工作区在侧边栏行上的 ⋯ 菜单里，用**默认对话预设**为它的 **+** 指定使用的预设。

预设字段大多在对话设置面板中编辑（更多选项 → **对话设置**，`Ctrl+Shift+,`）：

| 字段 | 含义 |
|---|---|
| 启用工具 | 模型可调用 {{SWITCHABLE_TOOL_COUNT}} 个可开关工具中的哪些。目录 {{TOOL_COUNT}} 个中其余 {{DERIVED_TOOL_COUNT}} 个由宿主从其他设置派生，从不出现在这里：六个记忆工具、`task_wait`、`task_list`、`box`、`web_search`、`web_fetch`、`skill`、`tool_search`、`plan` 和 `exit_plan_mode`。参见[内置工具](tools.html)。 |
| 代理角色 | 点名的子代理角色：它们跑在哪个模型上、拿到哪些工具、用哪个搜索后端，以及模型看到的一份说明。**允许无角色子代理**开关与它们在一起。 |
| 技能、MCP 服务器、钩子 | 按对话从全局 `~/.mework` 与本工作区 `.mework` 中发现的项目中选择。悬空的技能或 MCP 服务器会保持选中，并在运行时被跳过；不再能找到的钩子 id 会让运行失败，直到你取消勾选。 |
| 工具描述 | 此对话使用的提示词档案（工具描述文件）。默认使用内置英文档案。参见[提示词档案](prompt-profiles.html)。 |
| 联网搜索 | 一个**启用联网搜索**开关，然后是分别选择的搜索后端与抓取后端（原生提供商搜索或目录中的某家提供商，两者都能各自关掉）、一个结果数、一个结果压缩上限，以及域名白名单或黑名单。 |
| 记忆 | 两个相互独立的开关：全局记忆（`~/.mework`）和项目记忆（`<workspace>/.mework`）。 |
| 技能按需加载 | 关闭：选定技能的正文会粘贴到系统提示词中。开启：`skill` 工具会按需加载它们。 |
| 工具发现 | 关闭：每个选定 MCP 服务器的工具 schema 都预先声明。开启：只发出名字，`tool_search` 会取回运行中被扣下的 schema。 |
| 安全层级 | 手动（`request_approval`）、允许编辑（`allow_edits`）、计划模式（`plan`）或完全访问（`full_access`）——在输入框的安全层级菜单中选择，并随预设保存。见下文。 |
| 对话模板 | 仅限预设：套用预设时铺进对话的开局消息，其中可以有一条系统提示词。Mework 没有自己的系统提示词——不写时，组装出的提示词直接从宿主段落开始：先是环境段，然后是技能、MCP 服务器、钩子和应用数据行。进行中的对话没有模板页；它的时间线就是它自己的队列，可原地编辑。 |
| 拼接应用数据目录 | 仅限对话：在系统提示词中公开绝对应用数据路径。 |
| 推理强度 | 仅限对话：模型支持时会传递给提供商。 |

## 工具与批准 {#tools-and-approvals}

{{TOOL_COUNT}} 个内置工具，按组划分——每个工具在[内置工具](tools.html)下都有自己的页面：

- **文件系统** — `ls`、`grep`、`read`、`write`、`edit`、`find`（选择器里的 [`files`](tools.html#files) 一行）以及 `lsp`。受限于工作区和受信任根目录；符号链接、联接和 `..` 无法逃逸；写入是原子的，并返回差异。五道写入保护对每个对话、每个子代理恒常开启：对既有文件的 `edit`/`write` 要求先读取过；按文件修改时间已过期的写入会被拒绝，除非它是一次 `edit` 且其搜索文本在文件中仍恰好只匹配一处；你读过的文件的外部改动会在下一轮得到通报；钩子（格式化器）改写后会重新同步宿主对文件的记录；改动过你读过的文件的 Shell 格式化命令会被标记。`lsp` 由语言服务器作答（参见[代码语义导航](lsp.html)）；工作区自己的 `.mework/lsp.json` 点名的服务器会像一条命令那样请求批准，来自 `~/.mework/lsp.json` 或内置预设的则不会。
- **Shell** — `bash`、`zsh`、`sh`、`powershell`（选择器里的 [`shell`](tools.html#shell) 一行）：每个 shell 后端一个工具，对话中有机器装有该 shell 时才会列出。可在前台或后台（`run_in_background`）运行；批准卡显示的就是命令本身，折叠为一行。
- **网络** — `web_search`、`web_fetch`，以及 15 个 `preview_*` 工具（选择器里的 [`preview`](tools.html#preview) 一行）：把项目自己的开发服务器跑起来，并操作它渲染出的页面。
- **编排** — `agent_spawn`、`send_message`、`followup_task`、`task_wait`、`task_list`、`box`、`workflow`、`fork`、`skill`、`tool_search`、`todo`、`ask_user`、`plan`、`exit_plan_mode`。
- **记忆** — `read/create/edit_global_memory`、`read/create/edit_project_memory`。

**安全层级**决定哪些调用会先向你询问：

| 层级 | 读取工作区内内容 | 写入工作区内内容 | 读取外部内容 | 写入外部内容 | 子代理 | 分叉 | Shell、网络、浏览器、工作流 |
|---|---|---|---|---|---|---|---|
| `request_approval`（手动） | 允许 | 询问 | 询问 | 询问 | 询问 | 询问 | 询问 |
| `allow_edits`（允许编辑） | 允许 | 允许 | 允许 | 询问 | 允许 | 询问 | 询问 |
| `plan`（计划模式） | 同手动 | 拒绝 | 询问 | 拒绝 | 询问 | 询问 | 询问 |
| `full_access`（完全访问） | 允许 | 允许 | 允许 | 允许 | 允许 | 询问 | 允许 |

### 计划模式 {#plan-mode}

**计划模式**是只读的规划阶段：工作区读取与手动相同，而任何文件系统写入或编辑都会被直接拒绝，不会显示批准卡。Shell、联网搜索与抓取、包括截图在内的浏览器交互、工作流、MCP 调用和子代理派生仍和手动一样询问。进入计划模式只能由你在输入框的安全层级菜单里选择，模型没有请求进入的途径。处于计划模式时，宿主会自动提供两个派生工具，它们不会出现在工具选择器或预设中：`plan` 可读取或整体替换宿主存储的 Markdown 计划，`exit_plan_mode` 可提交计划供审阅。子代理会继承只读的计划模式，且永远不会获得这些工具。

调用 `exit_plan_mode` 会阻塞到你应答为止：计划面板在对话旁打开，批准卡就绘制在它里面。卡片提供**是，自动接受编辑**、**是，手动批准编辑**或**否，继续规划**三个选项；最后一项需要反馈文本，并让模型留在计划模式。已保存的计划还会以**实施计划**一行的形式出现在任务面板（更多选项 → 任务）中，点击它会打开同一个计划面板。任一“是”都会在同一回合中分别把对话切换到允许编辑或手动，输入框会立即显示新的层级。

有些确认无法由任何层级或钩子关闭：触及根目录、主目录或系统路径，或目标无法被分类器解析的递归删除；写入全局记忆；声明 `anthropic/requiresUserInteraction` 或被 `mcp.json` 列入 `disabledAutoApproveTools` 的 MCP 工具；以及接管你亲自登录过的浏览器页面。

批准卡会显示工具、参数的一行摘要（任何钩子重写之后）、风险级别以及这次调用为何被这样归类。**总是允许**会记住该对话中对此工具的决定，上限为你所回答卡片的风险级别；Shell 工具、MCP 工具和在页面上操作的 11 个 `preview_*` 工具永远拿不到长期许可。后台任务发出的卡片会在回合结束后继续保留，并在重新加载后再次出现。

`fork` 在包括完全访问在内的每个安全层级都会提出一张非阻塞请求卡，绝不自动创建子对话。子对话总是只带自己的 prompt 开始；批准和拒绝的决定会留在任务面板（更多选项 → 任务）中，但永远不会报告给模型。

## 运行环境

每个工作区都在一台机器上——本机、某个 WSL 发行版，或你登记的 SSH 机器——而 shell 是这台机器下的执行后端。Mework 会探测每台机器上它能用的 shell（本机在启动时，SSH 机器在每次启动后首次连接时，WSL 发行版在首次使用时，任何机器也可以在其设置里点**重新探测 shell**），并且只探测它支持的组合：Windows 上的 PowerShell 与 Git Bash，macOS、Linux 和 WSL 上的 zsh、Bash 与 sh。对话列出的 shell 工具是它所有机器的 shell 的并集，每个工具只能指定机器上有该 shell 的工作区。WSL 发行版和 SSH 机器还有一个**代理 shell**，就在该按钮右侧选择：远程文件工具、语言服务器和 Git 状态读取都经它运行脚本。新机器的代理 shell 按 Mework 为各系统固定的顺序，取它装有的第一个：Windows 上 PowerShell 先于 Bash；Linux 与 WSL 上依次是 Bash、zsh、sh；macOS 上依次是 zsh、Bash、sh。环境变量属于各个工作区，点工作区旁的齿轮编辑。批准会连同环境生成指纹，因此更改环境会使待处理的批准失效。

### 额外工作目录

那一排标签末尾的「文件夹加号」按钮，为本对话再添一个工作区之外、同样可以工作的目录。它打开的是工作区用的那个原生选择器，而这个选择器就是唯一的授权来源：宿主没有亲手交回来的路径，保存时会被拒绝——除了你自己的选择，没有任何东西能扩大一个对话的可及范围。每一份授权都是一个带 × 的标签，点一下即可交还。

模型是知道它们的：宿主那一半系统提示词以一段**环境段**开头，说明主工作目录、它是不是 Git 检出（以及是不是一棵隔离工作树）、每一个额外工作目录、平台、操作系统版本和今天的日期。它每一回合都按宿主自己的记录重新渲染，其中每一行都是一个你可以翻译或删掉的提示词档案键。

被授权的目录与工作区同等受信：其中的读取、写入与 Shell 路径不再算作越界，因此在「允许编辑」层级下不会再弹批准卡。它只属于你授权的那一个对话：预设、工作区快照和新建对话都不会继承，而分叉会继承——因为分叉本就持有父对话的权限。已被删除或拔掉的目录会直接从边界中剔除，而不是让调用失败。回合运行期间，这份集合被冻结。

## 子代理、工作流与任务 {#subagents-workflows-and-tasks}

持续运行的一切都是**任务**，并显示在任务面板中且带有停止按钮：子代理、工作流运行、后台 Shell 命令、终端和对话启动的开发服务器。

- `agent_spawn` 启动在后台运行的子代理（最多同时 8 个）。它获得父级的工具但去掉编排类——不能派生、没有 `workflow`、没有 `todo`、没有 `ask_user`、没有 `fork`，也看不到父级的任务面板——并在它自己持有任务生产者时得到自己的 `task_wait`/`task_list`。它仅在请求时（`context: "conversation"`）看到对话历史的副本，并携带来自提示词档案的子级附录。`send_message` 会将消息排队；`followup_task` 通过新回合唤醒空闲的子代理。`task_wait` 会阻塞至指定任务结算；未收集的任何内容会在下一轮边界以 `<task-notification>` 的形式发送。
- **角色**（预设或对话中的代理定义）让模型可按名称选择子代理；由你决定该名称背后的模型、工具和搜索后端。存在角色时，除非开启**允许无角色子代理**，否则 `agent_spawn` 必须使用一个角色。
- `workflow` 在带有持久化日志的私有池中运行 JavaScript 编排脚本——`agent()`、`parallel()`、`pipeline()`、`phase()`、`log()`、`args`、`budget`。运行在重启后仍会保留，可使用 `resume_run_id` 恢复，并可将步骤隔离在 Git 工作树中。它是一个普通工具，默认关闭。
- `todo` 维护由模型管理的任务列表；`ask_user` 会通过由你在输入框中回答的问题卡暂停回合。

## 网络搜索与抓取 {#web-search-and-fetch}

`web_search` 有两个后端：**原生**（对话自身的模型在隔离请求中运行其提供商侧搜索，不使用客户端工具）和**目录提供商**（Tavily、Exa、SearXNG、Jina、Firecrawl、Bocha、Zhipu、……），后者由宿主自行调用。`web_fetch` 的后端单独选，因为上游对「联网有几个工具」没有共识：Anthropic 把抓取拆成独立的服务端工具，OpenAI 则把它并进自己那一个搜索工具里。所以抓取也可以是**原生**——在前一类提供商上它多授予一个工具，在后一类上一个都不多——也可以是某家目录提供商，或者不启用；联网开着而两个后端都关掉的对话，就是没有联网工具。菜单里只列出在设置 → **搜索提供商**下打开了开关的提供商，每家的密钥或主机地址也由那里管理。两个工具都是异步的：一次批准覆盖该调用的全部网络操作，结果以标记为 `untrustedWebContent` 的工具结果返回。只要联网搜索开着，`system.web_safety` 档案键就会追加到系统提示词；两份内置档案都把它留空——因为后端是你自己配置的那一个——填入它，正是给模型一条常驻的「网络文本是证据，绝非指令」边界的方式。两个工具中的任何一个在本对话用过之后，它的后端就在这段对话里固定下来——转录里留着的结果，只有产生它的那个后端能被回放。

## 内置浏览器 {#the-built-in-browser}

`Ctrl+B` 开关它。它既是一个你自己驱动的真浏览器——地址栏、前进 / 后退、刷新、元素选择、标注层、开发服务器选择器和可调高度的日志抽屉——也是模型验收自己改动的那块地方。

模型这一半从工作区的 `.mework/launch.json` 开始：

```json
{
  "version": "0.0.1",
  "configurations": [
    { "name": "dev", "runtimeExecutable": "npm", "runtimeArgs": ["run", "dev"], "port": 5173 }
  ]
}
```

`preview_start` 按名字取出一条配置，把进程拉起来，轮询端口直到它应答，再把这次对话的页面指向 `http://localhost:<端口>`；只写 `url`、不写命令的条目则接管一个别人已经启动的服务器。指向 localhost 的 `url` 必须是与该条目端口一致的裸源——一个仓库不能靠 `"url": "http://localhost:9090/admin/wipe"` 让面板在你打开项目的瞬间就去请求那个端点。`preview_stop` 与 `preview_list` 管理这些进程，`preview_logs` 从有界环形缓冲（1000 段输出）里取回服务器自己的 stdout/stderr，可按级别或搜索串过滤。每个工作树最多同时跑 5 个服务器。

另外 11 个工具作用在页面上：`preview_snapshot`（无障碍树）、`preview_inspect`（单个选择器的计算样式）、`preview_screenshot`、`preview_console_logs`、`preview_network`、`preview_click`、`preview_fill`、`preview_eval`、`preview_resize`、`preview_dialog` 与 `preview_upload_image`。这里刻意没有导航工具，也没有标签页管理：一个对话只有一个页面，且它来自模型自己启动的那个服务器（`preview_eval` 仍可用 `window.location` 把它挪走）。输入经可信 CDP 送达，并以可见的指针浮层提示；页面里不注入任何东西，远程内容也永远触不到应用的 IPC 表面。

15 个中有 5 个只读宿主自己的状态，从不弹出批准卡：`preview_list`、`preview_logs`、`preview_snapshot`、`preview_inspect` 和 `preview_resize`。其余 10 个在完全访问以下都要询问。

只要 `.mework/launch.json` 可用且没有写成 `autoVerify: false`（默认就是开的，面板上的开关写的就是这个字段），系统提示词就会多出一段 `<preview_tools>`，讲的是「改完代码怎么验收」：先起服务器、必要时刷新，再读控制台 / 服务器 / 网络日志、取快照、查样式、试交互，最后用截图向你出示结果，而不是让你自己去看。关掉开关会从**下一步**起不再收到这段，而不是等到下一回合；没启用 `preview_start` 的对话同样收不到。

对话有多个工作区时，预览面板是按页面组织的：每个页面属于一个工作区，它的启动页列出那个工作区的 `.mework/launch.json`，起的服务器也跑在那个工作区所在的机器上；标签上的数字就是输入框上方工作区选择器里的编号。右上角的预览按钮会弹出工作区列表，选一个就为它打开一个页面，最下面一行开关面板——还没有任何页面时，打开的是输入框上方选中的那个工作区的启动页。面板里的 **+** 弹出同一份工作区列表。

SSH 机器上的工作区，开发服务器由那台机器上的 Mework 代理启动并托管，读配置、探端口、等就绪都在那台机器上完成；链路断开时服务器照常运行，输出留在那边，恢复后按序补齐。页面在本机渲染，但它的所有网络连接都经代理从那台机器发出——页面里的 `localhost`、它解析的每个主机名都是那台机器的，所以同机的其他端口（比如 API）也能直接访问。链路中断时面板会提示正在重连，而不是把超时当成页面故障。

每个页面都是一次性、隔离的 WebView2 Profile：不共享 Cookie，不会导入日常浏览器中的内容，关闭时即销毁。如果你亲自在某个页面上登录了网站，模型必须先请求批准才能在该页面上操作——这道确认任何安全层级和任何钩子都关不掉。

## 长期记忆 {#long-term-memory}

两层纯 Markdown，每层都有相同的布局：

```text
~/.mework/                       <workspace>/.mework/
  MEWORK.md                        MEWORK.md        standing instructions (you write these)
  memory/MEMORY.md                 memory/MEMORY.md index (the host maintains it)
  memory/<topic>.md                memory/<topic>.md memory documents (the model writes these)
```

启用某层的开关后，其 `MEWORK.md` 和 `MEMORY.md` 会粘贴到请求中，并且其三个工具可用；需要时按名称获取文档正文。写入全局记忆始终需要确认。记忆是模型的低优先级上下文，不是策略：必须始终成立的规则应写在钩子或安全层级中。

名为 `MEWORK.md` 的项目说明文件——在工作区里、在其 `.mework/` 里、沿上级目录直到项目边界、以及 `~/.mework/` 里——连同 `.mework/rules/*.md` 和一份由机器管理的策略文件，在启动时被发现，并作为不受信任的文件上下文块注入，独立于记忆开关。

## 图像与文件 {#images}

用 **+ → 上传文件**、粘贴，或把文件拖到输入框上，都能给消息添加附件；在时间线上编辑一条消息时，它也有自己的 **+**，同样可以粘贴和拖入。可以添加图像、PDF 和文本文件（源代码、Markdown、CSV、JSON、日志等）；拖动时，放置区域会说明将接收哪些内容，文件夹或不支持的格式在松手前就会显示为不可用。没有添加的项会连同原因一起列出。点击附件即可预览：PDF 按页排版，Markdown、HTML、CSV 和 notebook 会渲染出来，其他文本带行号显示。

每张图像都会在你的消息中获得一个模型可引用的 `[Image #N]` 占位符（所选模型需要支持图像输入）。产生图像的工具结果（对图像文件执行 `read`、`preview_screenshot`）也会获得编号，`preview_upload_image` 可将其中一张送进页面上的 file 输入框。文件以文字的形式交给模型，在请求发出时放在你的消息之前——PDF 是其各页的文字，所以没有文字层的扫描件会被拒收。文本文件最大 512 KB，PDF 最大 10 MB；一条消息最多带 20 个文件，文字合计约 40 万 tokens。粘贴一大段文字（5000 个字符或 100 行以上）时，它会变成 `pasted-text.md` 附件，而不是填满输入框。附件会以内容寻址方式存储在应用数据目录下。

## Git 与终端

**Git 审阅**面板把工作区的改动显示为一份差异——全部变更、仅已暂存或仅未暂存——可逐文件阅读，也可并排显示；每个文件都有暂存、取消暂存和一次需确认的丢弃，它还会把进行中的合并、变基、拣选提交、还原提交或二分查找推进到它的下一步。分支在输入框上方的标签中切换，同一排还能把对话放进一棵专属的**工作树**。**终端**面板以标签页的形式打开由你亲自操作的 shell——Windows 上是 PowerShell，其他平台是 `$SHELL`；模型只把每一个视为它可以等待的任务。

## 键盘、外观与依赖

设置 → **快捷键**列出应用的各条命令，并让你重新绑定它们（缩放快捷键固定）。**外观**涵盖主题、强调色、应用语言、缩放、字体、消息布局与渲染、发送与换行快捷键，以及自定义 CSS。**环境依赖**会在你的 `PATH` 中探测 `git`、`node`、`python`、`rg`、`fd`、`gh`、`uv`、`bun`，你也可以添加自己的命令和它的版本参数——仅检测，不会安装。

## 数据与重置

设置文档带有 schema 版本：由较新构建写入的文档会被拒绝而不是降级；加载失败的文档保持原样不动，旁边会写下一份 `document.corrupt-<timestamp>.json` 副本。若要在开发期间重新开始：

```bash
npm run reset:data           # wipe app data (add --keys to also remove stored API keys)
```

卸载应用不会删除 `%APPDATA%\com.mework.app`、`%LOCALAPPDATA%\com.mework.app`、凭据管理器条目或 `~/.mework`。
