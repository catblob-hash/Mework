# 技能

**技能**是包含 `SKILL.md` 文件的文件夹：为某一种任务打包的说明——部署清单、审查流程、仓库约定——还可以在其旁放置脚本和参考文件。其格式与 Claude Code、Codex 和公开技能注册表使用的格式相同，因此现有技能无需改动即可使用。

## `SKILL.md` 格式

```markdown
---
name: Commit helper
description: Prepare a conventional commit from the current diff
when_to_use: The user asks to commit, stage, or write a commit message
author: Example Org
version: 1.0.0
tags: [git, commits]
---

# Commit helper

1. Run `git status` and `git diff --staged`.
2. Group unrelated changes into separate commits.
3. Write a conventional commit message; run `scripts/check-message.sh` on it.
```

前置元数据是扁平的 `key: value` 键值对（并非完整 YAML）。Mework 只读取以下键：

| 键 | 用途 |
|---|---|
| `name` | 技能在目录中的标签。依次回退到第一个标题和目录名称。模型用技能的**目录名称**寻址它，而不是用这个标签。 |
| `description` | 显示在目录中；它与 `when_to_use` 一起构成模型看到的**触发**文本。回退到正文里第一行既非空也非标题的内容。 |
| `when_to_use` | 以 `description - when_to_use` 的形式追加到触发文本；键与该回退都拿不到任何描述时，它单独构成触发文本。 |
| `author`、`version`、`tags` | 解析后即丢弃：没有任何页面显示它们，它们也从不到达模型。标签可以是 `[a, b]` 或 `a, b`。 |

Claude Code 的其余前置元数据键——`allowed-tools`、`disable-model-invocation`、`user-invocable`、`model`、`context` 等——**一律忽略**。在这里，`skill` 工具是否暴露是一项对话设置，而不是前置元数据键。

**正文**（前置元数据之后的所有内容）是模型读取的内容。它是用户创作的内容，会逐字进入模型上下文，因此应将其写成给模型的说明。其中的相对路径（`scripts/…`、`references/…`）相对于技能目录解析：`skill` 工具会连同正文一起返回该目录，而拼进系统提示词的正文不带它。

## 技能的位置

技能**不会**被安装、导入或复制。Mework 扫描两个目录，并列出其中发现的内容：

```text
~/.mework/skills/<dir>/SKILL.md              用户范围——每个工作区
<workspace>/.mework/skills/<dir>/SKILL.md    工作区范围——仅该工作区
```

磁盘上的文件夹**就是**技能。编辑 `SKILL.md` 或它旁边的脚本，改动会在下一次运行时生效；删除文件夹，技能就消失了。扫描不递归：只有作为两个 `skills/` 文件夹之一的**直接子目录**、不是符号链接，并且其中有一份名为恰好 `SKILL.md` 的普通文件时，该目录才算作技能。符号链接的目录或清单会被忽略，因此链接无法把进入模型上下文的内容交给链接目标的拥有者。目录名不得包含 `(`、`)`、`,` 或控制字符，不得有首尾空白，也不得为空——这与 Claude Code 对斜杠命令的规则相同，在这里它还让模型称呼技能的那个名字保持无歧义。`SKILL.md` 最大为 256 KiB。

技能的身份是它的**目录名称**：这正是模型传递给 `skill` 工具的值，如同 Claude Code 中的 `/<name>`。前置元数据里的 `name` 和 `description` 只是目录展示的标签与触发文本。

## 内置的 Mework SDK 技能

应用只自带一个技能：**Mework SDK**（`mework-sdk`），它指导模型如何配置 Mework 自身——编写技能、`mcp.json`、`hooks.json`、`lsp.json`、提示词档案、`launch.json`、`MEWORK.md` 与规则，并在那些不是文件的设置上告诉你该去应用里的哪个位置。它编译在应用里，不写到磁盘上，因此随每个 Mework 版本更新、不能编辑、也没有删除按钮；它排在**技能**列表的最前面，出现在每个对话的列表里，与对话属于哪个工作区无关。

和所有技能一样，对话不勾选它就什么都不做：没有任何预设勾选它，内置的 **mework** 预设也不例外。想让模型替你配置或排查 Mework 时，在对话里勾上它。它的 id `skill_builtin_mework_sdk` 跨版本不变，所以你自己的预设勾选了它，升级后依然保留。按需加载时它以 `mework-sdk` 列出；它没有文件，`skill` 工具返回它时也不带基准目录。

对话抽屉的**技能**页面中，每个扫描发现的行都有一个删除按钮：第二次点击确认后，它会连同 `scripts/` 和 `references/` 一起删除技能的文件夹；对话上一次请求带着的技能，在模型缓存还热时画成橘色（见[工具锁定](tools.html#lock)）：经过缓存提醒后仍可以关掉，但没有删除按钮。页面工具条上还有一个**重新扫描**按钮和两个**打开文件夹**按钮——全局的 `~/.mework/skills`，加上本工作区的 `.mework/skills`（对话有工作区时）——目录不存在时它们会先创建它，再在系统文件管理器中打开。启动、打开设置面板、新增工作区以及每次删除之后也会重新扫描；每次运行都会自行重新扫描，因此运行用到的是那一刻磁盘上的内容。

## 为对话选择技能

被发现使技能可用；只有对话（或其起始预设）在**技能**页面选择它时，才会使用该技能。一个对话只能从全局 `~/.mework/skills` 加上**它自己工作区**的 `.mework/skills` 中选择；其他工作区的技能不会出现。预设可以保留任何 id。

被选中但文件夹已消失的 id——被改名或被删除——会保持选中，并显示为**悬空**行。它在运行时被**跳过**，因此删掉的文件夹绝不会让某个对话再也跑不起来；取消勾选该行即可移除。扫描能找到、但读不出内容的技能——`SKILL.md` 超过大小上限或不是 UTF-8——会以不可用状态显示并带上原因，选中它的运行会**失败**，直到你修好或取消勾选。

## 技能如何到达模型

**技能按需加载**开关（位于列表下方，始终显示）用于在两种机制之间选择：

- **关闭，开关读作*拼进提示词*——粘贴到系统提示词中。**每个选定技能的正文都会追加到系统提示词，以 `---` 行分隔。前置元数据会被剥掉；正文开头自带的标题会保留。模型会在每个回合读取技能，并在每个回合为其支付 token。
- **开启，*按需加载*——由 [`skill` 工具](tools/skill.html)加载。**系统提示词不包含正文，改为承载目录：一个 `Available skills:` 标题，每个有触发文本的技能各占一行 `- <名称>：<触发条件>`（[提示词档案](prompt-profiles.html)中的 `skill.listing_heading` 与 `skill.listing_row`）。`skill` 工具的 schema 不点名任何技能——它接受目录 `name` 作为字符串，因此在每个对话里都是同一个对象——调用后返回 `Base directory for this skill: <path>`，随后是正文（`skill.result`）。此模式下，两个目录重名的选定技能会被拒绝，因为同一个名字无法区分它们。

新对话从它起始的预设继承这个开关；内置的 **mework** 预设开局是开的。

无论哪种方式，对话**开局**带的那批技能就是它系统提示词的内容，此后这份提示词不再变化。之后再选的技能会在时间线的那个位置经 [`box` 工具](tools/box.html)以宿主消息送达——传递关闭时是正文，开启时是触发行（`system.skill_added_body` / `system.skill_added_trigger`，摘要是 `host_notice.skill_added_summary`）——排在它前面的已缓存提示词保持原样。取消某个技能、或改动传递开关，则会重写那份提示词，所以缓存还热的时候两者都画成橘色；但都不会被拒绝。

`skill` 工具是派生出来的，不在工具选择器中：仅当开关开启且至少一个选定技能成功解析时才会出现。子代理会继承父对话所选的技能。

## 验证技能是否已激活

- 传递**关闭**时，下一条模型回复会遵循技能说明；**发出的请求**面板（更多选项 → 发出的请求）会在系统提示词内、`---` 分隔符之后显示正文。
- 传递**开启**时，时间线会显示一张 `skill` 工具调用卡；模型加载技能时，其结果以基础目录行开头。

## 故障排除

| 症状 | 原因 |
|---|---|
| Mework SDK 没有删除按钮 | 它内置在应用里。不想用时取消勾选即可。 |
| 对话抽屉中没有该技能 | 它的文件夹不是 `~/.mework/skills` 或本工作区 `.mework/skills` 的直接子目录，或缺少 `SKILL.md`，或是符号链接，或其名称包含 `(`、`)`、`,`，或有首尾空白。 |
| 显示为不可用 | Mework 找到了文件夹，但读不出 `SKILL.md`：超过 256 KiB、不是 UTF-8，或无法读取。选中它的运行会以该原因失败。 |
| 显示为*悬空* | 所选 id 的文件夹已被改名或删除。运行时忽略它；取消勾选该行即可移除。 |
| 两个技能目录名称相同，且按需加载失败 | 重命名其中一个目录，或仅选择其中一个。 |
| 两个技能显示名称相同 | 无碍——模型按目录名称选择，不按标签。 |
| 技能改动没有反映出来 | 目录是一份快照。按页面上的**重新扫描**；启动、打开设置面板和删除条目时也会扫描。 |
