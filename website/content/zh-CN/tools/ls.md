`ls` 列出工作区中某个目录里的内容。模型会用它在一棵没见过的目录树里辨认方向——有哪些文件夹、某个包目录里装着什么——然后再决定去 `read` 什么。`path` 是相对路径时始终相对工作区解析，即使某次批准已把范围扩展到工作区之外。

## 审批

调用被归类为读取。在工作区、应用数据目录以及授予本对话的任何额外工作目录之内，列目录在所有安全层级下都无需询问，计划模式也在内。落在这些根之外的路径属于外部读取：`request_approval` 和计划模式会弹批准卡，`allow_edits` 和 `full_access` 直接放行。**总是允许**可以在本对话中为这个工具记住外部列目录，上限为你所回答卡片的风险级别，应用重启后即被遗忘。有一个目录在任何级别都会被拒绝且无法批准：应用数据目录下的 `memory/`，只有长期记忆工具才能打开它。

## 行为与限制

遍历是广度优先的——先列出下一层的全部条目，再列下两层的全部条目，直到 `depth`，每个目录内按名字顺序——从不跟随符号链接或联接，每个条目在被展示或深入之前，都要先对照授权范围检查。条目经过排序、以正斜杠书写，目录结尾带一个 `/`。

哪些目录不展开，按 Git 的判断来定。在 Git 工作树里，`git ls-files` 报告为被忽略的目录会列出来、标上 `(ignored)`，但不进入；在工作树之外，依赖和构建目录按名字同样处理（`node_modules`、`vendor`、`target`、`build`、`dist`、`.venv`、`__pycache__` 等）。`.git` 这类版本控制目录从不进入。被忽略的文件照常列出；本身就被忽略的 `path` 之下的一切也照常列出：点名 `target/debug`，得到的就是 `target/debug`。在远端工作区上，由那台机器自己的 `git` 判断。

回答在 40,000 字符处停止。因为遍历是广度优先的，上限截掉的是到达的最深一层，最后一行会说明列表完整到哪个深度。空目录回答 `(empty directory)`；读不了的子目录产生一行 `[skipped]`，而被列的目录本身打不开会让调用失败。
