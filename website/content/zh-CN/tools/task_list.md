`task_list` 是模型眼中的对话任务面板：子代理、工作流运行、终端、开发服务器和后台命令，无论正在运行还是早已结束，每一项都带着它应答的地址。模型会在等待某个东西之前，或者重新接起一段对话之后，用到它。

## 审批

它只读取宿主状态，别无其他，因此任何安全层级都不会询问它。

## 行为与限制

清单以一个计数开头，行按子代理、工作流、终端、开发服务器和 Shell 命令分组。每行先打印可以原样交给 `task_wait` 的地址——裸代理名、`workflow:<runId>`、`terminal:<id>`、`preview:<serverId>` 或 `shell:<id>`——然后是状态、与地址不同时才打印的显示标签、压缩到 120 字符的行详情预览（子代理的任务文本、终端的 Shell 与工作目录、开发服务器的 `localhost:<port>`（在别的机器上时还有那台机器）、Shell 行运行过的命令），以及任务发出过的最近一次进度更新。

开发服务器列自对话的每一个工作区。两个工作区可以都有一台 `dev`，所以有多个工作区时，开发服务器的地址带上工作区编号：`preview:dev@2`。

已结束的子代理会带着它结束时的状态留在清单上。没有什么能让它继续——子代理只按派生时拿到的任务运行一次。来自更早回合、已经离开池子的子代理或工作流运行，会说明它的结果在时间线里。已结束的命令会带着退出码留在清单上，因此这份清单能回答那次构建是否通过，而不只是什么正在运行。

对话里一个任务也没有时，只会得到一行说明这一点的文字。整份清单上限为 64 KiB。
