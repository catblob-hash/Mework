`grep` 用正则表达式逐行搜索文本文件，并以 `path:line:content` 的形式返回命中。模型在打开任何文件之前会用它找到符号、字符串或 TODO 究竟在哪里，也会用它确认一次重命名没有留下残余。`path` 可以是单个文件，也可以是被递归搜索的目录。

## 审批

调用被归类为读取。停留在工作区、应用数据目录或授予本对话的额外工作目录之内的搜索，在所有安全层级下都无需询问，计划模式也在内。落在这些根之外的路径在 `request_approval` 和计划模式下询问，在 `allow_edits` 和 `full_access` 下放行；**总是允许**可以在本对话中为这个工具记住这一决定，上限为你所回答卡片的风险级别。应用数据目录下的 `memory/` 在任何级别都被拒绝，`full_access` 也不例外。

## 行为与限制

模式使用 Rust `regex` 语法——字符类、交替、锚点与重复，但没有反向引用或环视——且每一行都单独匹配，因此 `^` 和 `$` 锚定的是行首与行尾。

在 Git 工作树里，搜索范围就是 Git 会展示的内容：已跟踪的文件，以及没有被忽略的未跟踪文件，所以构建产物、`node_modules` 以及 `.gitignore` 里写的其他东西都不会产生命中。在工作树之外，依赖和构建目录按名字跳过，规则同 [ls](ls.html)。版本控制目录从不搜索。指向被忽略目录内部的 `path` 会被完整搜索，作为 `path` 点名的单个文件不论规则如何都会搜索。不跟随符号链接。大于 2 MiB 的文件会被跳过，前 8,192 字节中含 NUL 字节的文件同样如此——二进制文件就是这样被识别出来的；其余位置无效的 UTF-8 会被替换而不是导致失败。

行号从 1 开始，每条报告出来的行在 500 字符处截断。一次调用返回 250 条匹配行，除非 `limit` 要求别的数目，最多 1,000；后面还有时，最后一行给出下一页的 `offset`，`offset` 最大 100,000。读不了的条目产生一行 `[skipped]`（前 20 个逐一列出，其余计数），而不是让调用失败；没有任何命中时回答 `No matches found`。超过 20,000 字符的结果会保存到应用数据目录下的一个文件里，换成该文件的路径和前 2,000 个字符；其余部分用 `read` 或 `grep` 去读那个文件。
