`find_output` 在本对话运行过的一条 shell 命令的输出里查找，只返回和一句自然语言 `query` 相符的部分，而模型不必读整段记录。当一次构建、一轮测试或一份服务器日志长到没法整段读完——仍在运行的后台命令、因超时被移交任务面板的命令、结果早已滚出视野的已结束命令——而模型知道自己要找什么时，就会用它：第一个错误、迁移有没有跑、哪个测试卡住了。命令用 `task_list` 打印的 `shell:<id>` 地址指定；只给 id 也按同样的方式解析。

## 审批

它读取的是宿主自己保存的那份命令输出，什么也不启动——不碰文件、不起进程、不动页面——因此被归类为低风险读操作（`host.read_or_coordinate`），任何安全层级都不会询问它，计划模式也在内。把块发给 TypeSafe 不需要另行审批：打开这个工具并存好密钥，本身就是你的同意。

## 行为与限制

只能解析本对话的命令：属于别的对话的地址，读起来和从未存在过的地址一模一样；`terminal:`、`workflow:` 或 `preview:` 地址会被当作不是 shell 任务而拒绝。凡是 shell 工具运行过的命令都算数——前台或后台、正在运行或已经结束、任何一个 shell，筛选输出形式也在内。被打分的是任务面板保留的内容：最后 256 KiB，标准输出和标准错误按到达顺序交错排列，而不像工具结果那样分组。开头已被丢掉时，回答会说明丢了多少字节，行号从仍保留的第一行算起。正在运行的命令读到它当前为止的输出；不会等它。已结束的命令在重启之后仍然可读，直到对话里已结束的命令超过 400 条、或它们的输出超过 32 MiB，最早的才会被丢弃；Mework 退出时仍在运行的命令，读出来是已结束、没有退出码。

回答以宿主自己写的一行状态开头——`shell:3 (bash) is still running`、`shell:3 (bash) was stopped`、`shell:3 (bash) finished with exit code 1`——这一行从不打分，也从不发送。什么都没打印过的命令回答 `shell:3 has produced no output to score.`，不发出任何请求，所以这个回答不需要密钥。`query` 会去掉首尾空白，上限 2,000 字符；`threshold` 必须在 0 到 1 之间，并四舍五入到三位小数。

文本被切成日志记录，也就是这个工具打分和返回的块：一行连同接续它的行——缩进更深的行（比如堆栈）、`Caused by:`，以及结束 Python traceback 的那一行异常。命令的输出不保留它是怎么写出来的——保留下来的输出是一整段字节流，而且程序往管道写时通常按 4 KiB 一块刷出——所以记录只能从文本本身读出来。空行不打分。每个块都单独打分，各有自己的一个问题，几个块共用一次请求：一次请求装多少块由请求预算决定——材料短时每次 1,500 字符，长一些时让一次调用保持在 150 次请求左右，最多 12,000 字符——且一次最多 32 块。请求同时发出八个，而且 Mework 发往 TypeSafe 的所有请求共用一个节奏——空闲一阵后可以一次发 32 个，之后每秒 18 个，低于 TypeSafe 每分钟 1,200 次的上限——所以材料很长时只是花的时间更长，不会有一部分没打分就返回。超过 12,000 字符的块分成几部分打分——沿行切，更长的单行按字符切——块的分数取得分最高的那一部分；它照样完整返回，标题里注明得分最高的那部分在哪几行。

状态行之后是一行计数——`1 hit at or above 0.600 for query "…" (212 records of shell:3 output scored, 7 requests).`——然后按分数从高到低列出每条达标的记录，形如 `--- shell:3 output lines 212-214 (score 1.000) ---`，下面是完整的记录，每行带它在输出里的行号，格式同 `cat -n`。分数和阈值一样保留三位小数，因此报告出来的分数可以直接当作阈值传回去。没有任何记录达标时，回答会说明这一点，并列出分数最高的三条记录及其分数。输出超过 64 KiB 会被截断。

`429` 和 `529` 的回应会重试两次，分别等 1 秒和 2 秒，或按服务器的 `Retry-After` 等待、最多 10 秒；每次尝试限时 30 秒。仍然失败的请求会让它里面的块不计分，回答会报出失败的请求数和因此没打分的块数；只有什么都没打出分时，调用才会失败。缺少密钥、或密钥被 TypeSafe 拒绝时，调用失败，并附一条指向密钥设置的消息。停止运行会立即返回 `nothing was returned`；已经发出的请求自行跑完。

## 决策模型

`find_output` 在工具选择器的 **Shell** 分组里自成一行，标着**决策模型**，挨着 `shell` 那一行，而不在它打开的窗口里；分组标题上的 **+** 会把它和各个 shell 一起打开。预置的预设不会打开它，因为在「全局设置 → 决策模型提供商」里存好 TypeSafe 密钥之前它无法运行。每次请求向 TypeSafe 的 API 发送查询，以及其中每条记录的标签——`shell:<id> output` 加上行号范围——和文本；状态行和命令本身都留在本机。分数是 Jev 在四个级别上按概率加权给出的回答——无关、略有相关、相关（包含所问内容的一部分）、正中——映射到 0 到 1，所以四个级别分别落在 0、0.333、0.667 和 1。
