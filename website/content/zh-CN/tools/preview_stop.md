`preview_stop` 会杀掉本对话可寻址的一台开发服务器并把它忘掉，缓冲输出也一并丢弃。当一台服务器碍事时——它占着下一次启动所需的端口，或工作树已到五台上限——或者当这台服务器所服务的工作已经完成时，模型就会用到它。`serverId` 是服务器在 `launch.json` 里的名字——重名时带编号——也就是 `preview_list` 报告的那个。

## 审批

杀掉项目 `launch.json` 描述的进程是无界操作（`tool.unbounded`，高风险）：手动与允许编辑会询问，完全访问不会。**总是允许**可以回答这张卡，并记住本对话中对此工具的决定。缺失、空白或非字符串的 `serverId` 会在弹出任何卡片之前就被拒绝。

## 行为与限制

只有本对话各工作区里、由本对话启动或无人拥有的服务器才能被停止。任何其他 id——别的对话的服务器、已经退出的、从未存在过的——都会以 `Server <id> not found` 应答。成功则以 `Server <id> stopped` 应答。

两个工作区可以各有一台 `dev`，所以有多个工作区时，`workspace` 补全地址。只有一个工作区有这个 id 的服务器时可以省略；多个工作区都有而调用省略了它，会被拒绝并列出这些工作区的编号；指定的工作区里没有这台服务器，则会被拒绝并列出有它的工作区。

被杀的是整棵进程树，而不只是被拉起的那个子进程，因此包装脚本没法把真正的服务器留下来。服务器的日志环形缓冲随它一起丢弃，所以如果输出还要用，先读 `preview_logs`。之后再启动同一条目，它仍以同一个 id 回来。

接管条目的 id 背后没有进程，会被一句话拒绝，说明没有可停止的东西。停止一台服务器会连带把它的预览页关掉。自行退出的服务器也会离开列表，但它的页面仍然开着，因为页面此时显示的内容——连接被拒绝、退出途中打印的堆栈——正是诊断所在。应用退出时会停止所有服务器。
