`todo` 是对话自己的任务清单：模型为它答应要做的工作建立条目，把它们沿 `pending` → `in_progress` → `completed` 推进，并能记录哪个条目阻塞哪个。清单绘制在任务面板顶部，是一份可折叠的计划，带进度条、已完成数与总数、以及活动条目的现在进行时措辞。它是用户看得见的簿记，不是调度器——条目存在并不让任何东西运行。

## 审批

任何安全层级都不会询问。`get` 与 `list` 被归类为对宿主状态的读取；`create` 与 `update` 被归类为对本对话自身状态的更改——两者都触及不到文件、Shell 或网络。宿主读不懂的 `action` 按写入归类，那是两者中更严格的一个。这个工具只由模型运行循环调度，不能手工执行。

## 行为与限制

清单在每次运行开始时通过重放本对话成功的 `todo` 结果重建，所以它跟随转录：删掉或编辑那些消息，清单也随它们变化。ID 按顺序铸为 `task-1`、`task-2`……，一份清单最多容纳 1,000 个条目。任务不能阻塞自己，也不能被自己阻塞，每个关联 ID 必须已经存在，依赖环会被拒绝。仍被某个未完成任务阻塞的任务不能变成 `in_progress` 或 `completed`——被阻塞期间只有 `pending` 是合法的。`status: "deleted"` 移除该条目以及其他条目里对它的每一处引用。读取一个不存在的 ID 会以 null 任务作答而不是失败。子代理永远拿不到这个工具。
