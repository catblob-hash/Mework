`lsp` 工具向语言服务器询问**符号**而不是文本：一个名字定义在哪、谁引用了它、它的类型是什么、谁调用这个函数。Mework 以 Language Server Protocol 与你的编辑器所用的同一批服务器对话。当问题关乎声明或调用方而非字符串时，模型就会使用它。

## 审批

普通调用被归类为对 `filePath` 的一次**读**：文件在工作区内时任何层级都放行，落在工作区外时，手动与计划模式会询问。如果工作区自带 `.mework/lsp.json`，每次调用就转而归类为**无界操作**，并在完全访问以下的每个层级询问——那份文件指定了 Mework 启动的命令，而受检查的只是它存不存在，从不看其内容。工作区没有这份文件时，来自 `~/.mework/lsp.json` 或内置预设的服务器什么也不会弹出。**总是允许**会为该对话记住这个答案，上限为你所回答卡片的风险级别。缺失、为空或超过 64 个字符的 `operation` 会在任何路径处理之前被拒绝。

## 行为与限制

回答是自然语言，不是 JSON：位置写成相对工作区根的 `path:line:character`，什么都没匹配上的问题会用一句话回答，而不是报错。`git` 在 `PATH` 上时，被 git 忽略的文件里的命中会从定义、引用、实现与工作区符号的结果中剔除。服务器在第一次有请求问到它管的文件时启动，由该工作区的所有对话共享，并随应用退出而停止——所以项目里的第一次调用可能很慢，也可能在它还在建索引时返回空。超过 10 MB 的文件不会发送；请求 30 秒无人应答就会失败，并以此作为失败原因。
