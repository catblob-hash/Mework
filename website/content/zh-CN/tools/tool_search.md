开启**工具发现**后，对话的 MCP 工具只按名字公告，schema 被扣留；`tool_search` 就是模型取回所需那个工具 schema 的途径。它接受一个 query，与被扣留的名单匹配，然后以已声明工具集所用的同一 `<functions>` 编码返回匹配工具的完整 JSONSchema 定义。

## 审批

任何安全层级都不会询问。schema 在回合开始时就被发现，已经装在请求里，因此发出其中一份不会触及运行之外的任何东西。MCP 工具本身是另一回事：调用它会像任何 MCP 调用一样被单独归类与审批。

## 行为与限制

只有在发现开启且本次运行至少扣留了一个工具时，这个工具才会出现。`select:` 查询按精确名字解析（逗号分隔、不区分大小写），并返回它找到的每一个；解析不到的名字就干脆缺席，而一条什么都没解析到的查询会答复当前有多少工具被延迟声明、它们的名字列在哪里。任何其他查询都是对被扣留名字、其服务器及其描述的关键词搜索，MCP 名字会拆成服务器与工具两段词，任一半都能命中。schema 一旦发出，该工具就从下一步起像其他工具一样被声明，直接调用即可——无需再次搜索。被扣留名字的公告在整个运行期间固定，不会随 schema 到达而缩减。子代理连接相同的服务器并扣留相同的工具；它起步时不带父对话取回过的任何一份 schema。一旦对话连接过某台服务器，开关本身就会冻结，因为转录已经按其中一种方式携带了它的工具。
