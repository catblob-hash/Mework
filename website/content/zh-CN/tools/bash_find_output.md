`bash_find_output` 和 [bash](bash.html) 完全一样地运行一条命令行，然后把输出交给 TypeSafe Jev 决策模型，而不是交给对话：只有和这次调用的 `query` 相符、分数不低于 `threshold` 的部分才会返回。当模型在运行命令之前就知道自己只想从一大段输出里取一件事——测试为什么失败、构建断在哪里、哪个包引入了某个版本——而不要其余部分时，就会用它。它是 `bash` 的决策模型形式，在 Shell 工具窗口里选择。

## 审批

与 `bash` 完全相同：每次调用都会在手动、允许编辑与计划模式弹出卡片，卡片上显示命令；只有完全访问——或一个回答 `allow` 的 `PreToolUse` 钩子——能放行。命令经过同样的静态分析，它只决定卡片的风险级别与规则；也同样会遇到那道任何安全层级和任何钩子都关不掉的递归删除确认。钩子看到的是这个调用自己的名字，所以写成 `^bash$` 的匹配器覆盖不到它。不提供**总是允许**，也没有操作系统级的沙箱。把输出发给 TypeSafe 不需要另行审批：打开这个工具并存好密钥，本身就是你的同意。

## 行为与限制

命令走的就是 `bash` 自己的路径——同样的 shell、rc 快照和目录规则，同样的 `timeout` 钳制（默认 120000 毫秒，最多 600000 毫秒）——并以一条 `bash` 命令登记在任务面板上，它的输出留在那里，[find_output](find_output.html) 可以再次查找。有两点不同：没有 `run_in_background`；命令到达 `timeout` 时会被停止，而不是转入后台，超时说明就成为它的状态行。

被打分的是 `bash` 为模型捕获的那份输出：标准输出和标准错误各自的前 64 KiB——成功时标准输出在前，失败时标准错误在前——任何一路被截断时，末尾还有一行截断说明。失败调用的状态行——`Exit code N`、中止说明或超时说明——原样保留在报告上方，从不发送；成功的调用没有状态行，所以第 1 行就是输出的第一行。格式化类命令之后，那条点名你读过、又被它改动了的文件的提示跟在报告后面，而不参与打分。什么都没打印就失败的命令，返回的是它的状态行和 `(no output)`，不发出任何请求；什么都没打印就成功的命令，只剩 Mework 自己补上的那行完成说明可供打分。调用的成败随命令本身，与有没有内容达到阈值无关。

打分就是 [find_output](find_output.html) 的那一遍：输出切成日志记录，每条记录单独打分、几条共用一次请求，同时发出八个请求，遵循 Mework 发往 TypeSafe 的共用节奏。回答是一行计数——`1 hit at or above 0.600 for query "why the run failed" (40 records of the command output scored, 2 requests).`——然后按分数从高到低列出每条达标的记录，形如 `--- output line 31 (score 1.000) ---`，下面是带行号的记录；没有任何记录达标时，则列出分数最高的三条记录及其分数。

`query`、`threshold` 和密钥都要等命令运行完才检查。缺少参数、缺少密钥或密钥被拒、所有请求都失败，都会让调用在命令的效果已经落地之后失败；这时它的输出只在它的任务面板上。

## 决策模型

在对话的 **Shell** 工具窗口里，**Bash** 打开之后，**加上决策模型参数**会同时启用 `bash` 和 `bash_find_output`，由模型逐次选择；**只用决策模型**只留下 `bash_find_output`，完整输出和后台运行随普通 `bash` 一起不再提供。运行一旦把某个工具展示给过模型，它在这个对话余下的时间里就一直开着，所以两者之一出去过之后，只能选仍然保留它的形式。预置的预设不会打开 `bash_find_output`，因为在「全局设置 → 决策模型提供商」里存好 TypeSafe 密钥之前它无法运行。每次请求向 TypeSafe 的 API 发送查询，以及其中每条记录的标签（`output` 加上行号范围）和文本；命令和它的状态行都留在本机。
