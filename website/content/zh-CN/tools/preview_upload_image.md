把一张已经存在于对话里的图片放进预览页面上的 file 输入框。模型在它正在测试的页面需要一次真实上传时用它；它也是唯一能清掉页面已打开的文件选择器的动作。

## 审批

一次调用把本地数据送往页面（`browser.image_upload`，高风险），因此在 `request_approval` 和 `allow_edits` 下会询问；只有 `full_access` 不问。**总是允许**不会记住任何页面工具，而且在你亲自登录过的页面上，接管确认会先出现，任何安全层级和任何钩子都替你答不了。没有手工执行这条路：图片编号只有在一次实时运行里才有意义，因此在运行之外执行或批准这个工具都会被直接拒绝。

## 行为与限制

`image_id` 按转录解析：你附上的图片和工具产出的图片都算，记忆工具除外。宿主把这些字节写进一个一次性的临时目录，把真实路径交给页面，事后无论上传成功与否都会删掉它。模型永远不提供文件系统路径。

页面可见的名字来自 `filename` 或附件本身：Windows 禁用的字符会被替换，没有扩展名时按图片类型补一个，上限 160 字节。隐藏的输入框也能用；不要求可见。没有文件选择器打开时，调用必须给出 `selector`；不会回退到页面上的第一个 file 输入框。

结果报告元素、文件数、图片编号与名字，以及页面在平复之后的样子。它只公告给看得见图像的模型；调用限时 30 秒。
