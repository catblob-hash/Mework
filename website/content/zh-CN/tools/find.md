`find` 按 glob 定位文件和目录，范围是工作区中某个目录之下的任何位置。当模型知道某个东西叫什么、却不知道它住在哪里时——每一个 `*.test.ts`、某个叫得出名字的配置文件、一个包所在的目录——就会用它，然后对返回的结果做 `read` 或 `grep`。

## 审批

调用被归类为读取。工作区、应用数据目录或授予本对话的额外工作目录之内的搜索，在所有安全层级下都无需询问，计划模式也在内。落在这些根之外的 `path` 在 `request_approval` 和计划模式下询问，在 `allow_edits` 和 `full_access` 下放行；**总是允许**可以在本对话中为这个工具记住这一决定，上限为你所回答卡片的风险级别。应用数据目录下的 `memory/` 在任何级别都被拒绝，`full_access` 也不例外。

## 行为与限制

模式使用普通的 glob 语法——`?`、`*`、`**`、字符类和 `{a,b}` 交替——并且区分大小写。`*` 不会被路径分隔符拦住，而 `**` 只有作为完整的路径段才是合法的；写在任何其他位置都是模式错误。每个条目都会拿它相对被搜索目录的路径和它的裸文件名各测一次，命中任意一个即算数。搜索完全递归，不跟随符号链接。和 `grep` 不同，它不隐藏任何被 Git 忽略的东西，因为按名字查找时要找的往往恰恰是被忽略的那个文件——`.env`、生成的头文件。落在被忽略路径里的匹配（工作树里按 Git 的规则，工作树外按依赖和构建目录）排在其他匹配之后、标上 `(ignored)`，并有一行说明共有多少条。版本控制目录可以按名字命中，但不会进入遍历。目录同样能命中，返回时带一个结尾的 `/`。每组分别排序、以正斜杠书写。

最多返回 100 条匹配，更多时有一行给出总数；遍历最多检查 200,000 个条目，提前停下时会说明。没有任何匹配时回答 `No matching files`。
