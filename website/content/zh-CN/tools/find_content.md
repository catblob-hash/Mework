`find_content` 找出一个文本文件里哪些地方包含一句自然语言查询所描述的内容，而模型不必去读这个文件：文件被切成它自己的块——函数和其他符号、章节、段落——TypeSafe Jev 决策模型对照查询给每一块打分，达到这次调用 `threshold` 的每一块都完整返回，带着行号范围，每行带行号。当一个文件长得没法整个读完——大模块、日志、生成出来的规范——而模型知道自己要找什么、却不知道它是用哪些字眼写成的，就会用它，这正是 `grep` 力所不及的地方。命中的行号可以直接交给 `read` 或 `edit`。

## 审批

调用被归类为读取，按与 `read` 相同的路径规则判断。工作区、应用数据目录或授予本对话的额外工作目录之内的文件，在所有安全层级下都无需询问即可打分，计划模式也在内。落在这些根之外的文件在 `request_approval` 和计划模式下询问，在 `allow_edits` 和 `full_access` 下放行；**总是允许**可以在本对话中为这个工具记住这一决定，上限为你所回答卡片的风险级别。应用数据目录下的 `memory/` 在任何级别都被拒绝，`full_access` 也不例外。把块发给 TypeSafe 不需要另行审批：打开这个工具并存好密钥，本身就是你的同意。

## 行为与限制

目标必须是不超过 2 MiB 的普通 UTF-8 文本文件。图像——带 PNG、JPEG、GIF 或 WebP 签名的文件——会以 `<path> is an image; only text files can be scored` 被拒绝；空文件回答 `<path> is empty; there is nothing to score.`，不发出任何请求。`start_line`（默认 1）和 `end_line`（包含该行，默认最后一行）选定范围；与 `read` 不同，这里没有行数上限，超出末尾的 `end_line` 会被收到末尾，超出末尾的 `start_line` 则是错误。`query` 会去掉首尾空白，上限 2,000 字符；`threshold` 必须在 0 到 1 之间，并四舍五入到三位小数。

范围被切成文件自己的原始块——组成文件的最内层单元——块就是打分的单位，也是返回的单位，而且总是完整返回。有语言服务器认领这个文件时，块是它报告的最内层文档符号：内部不再嵌套符号的函数、方法或其他符号，连同紧贴在它上方、缩进相同的注释和属性行。`impl` 或类这样的容器本身不是块：它的成员才是，它自己的开头行和收尾行各自成块。这台服务器必须是 Mework 不用询问就能启动的——内置预设，或你自己 `~/.mework/lsp.json` 里的——若是工作区自己的 `.mework/lsp.json` 指定的，则必须已经由一次经过批准的 `lsp` 调用启动过；等它回答最多 5 秒，冷启动需要更久的服务器会在后台继续启动，留给下一次调用。Markdown 文件按章节切，一个标题连同到下一个任意级别标题之前的内容是一块。其余情况——符号之间的行、没有服务器及时回答的文件、WSL 或 SSH 机器上的文件——按缩进切：一行连同其下缩进更深的行和收尾的 `}`、`)`、`]`、`end` 或 `fi`，再加上紧贴在它上方的注释和属性，是一块；空行之间连续的单行块在 1,500 字符以内算一个段落（一段散文、一串 import），超过则视为数据，每行一块；超过 12,000 字符、里面包含两个以上带主体的块的块被当作容器，拆成它的开头、成员和收尾行。块之间的空行不打分。每个块都单独打分，各有自己的一个问题，几个块共用一次请求：一次请求装多少块由请求预算决定——材料短时每次 1,500 字符，长一些时让一次调用保持在 150 次请求左右，最多 12,000 字符——且一次最多 32 块。请求同时发出八个，而且 Mework 发往 TypeSafe 的所有请求共用一个节奏——空闲一阵后可以一次发 32 个，之后每秒 18 个，低于 TypeSafe 每分钟 1,200 次的上限——所以材料很长时只是花的时间更长，不会有一部分没打分就返回。超过 12,000 字符的块分成几部分打分——沿行切，更长的单行按字符切——块的分数取得分最高的那一部分；它照样完整返回，标题里注明得分最高的那部分在哪几行。

回答以一行计数开头——`1 hit at or above 0.600 for query "…" (40 blocks of src/auth.rs scored, 3 requests).`——然后按分数从高到低列出每个达标的块，形如 `--- src/auth.rs lines 29-47 (score 1.000) ---`，下面是完整的块，每行前面是它在文件里的行号，右对齐占六列再加一个制表符，和 `cat -n` 的格式一样。行号只给读者看，决策模型从不会看到。路径相对于工作区。分数和阈值一样保留三位小数，因此报告出来的分数可以直接当作阈值传回去。没有任何块达标时，回答会说明这一点，并列出分数最高的三个块及其分数；有请求失败时，回答会说明失败了几次、留下几块没打分。命中不算读取：`edit` 和 `write` 仍然要求先 `read` 过这个文件。输出超过 64 KiB 会被截断，所以很长的块返回时可能不完整。

`429` 和 `529` 的回应会重试两次，分别等 1 秒和 2 秒，或按服务器的 `Retry-After` 等待、最多 10 秒；每次尝试限时 30 秒。仍然失败的请求会让它里面的块不计分，回答会报出失败的请求数和因此没打分的块数；只有什么都没打出分时，调用才会失败。缺少密钥、或密钥被 TypeSafe 拒绝时，调用失败，并附一条指向密钥设置的消息。停止运行会立即返回 `nothing was returned`；已经发出的请求自行跑完。在 WSL 或 SSH 工作区上，文件在那台机器上读取，文本传回来之后按同样的限制打分。

## 决策模型

`find_content` 在工具选择器的**文件与搜索**分组里自成一行，标着**决策模型**，不在 `files` 那一行打开的**文件工具**窗口里。预置的预设不会打开它，因为在「全局设置 → 决策模型提供商」里存好 TypeSafe 密钥之前它无法运行；密钥保存在操作系统的凭据存储里。每次请求向 TypeSafe 的 API 发送查询，以及其中每一块的标签——相对工作区的路径和行号范围——和文本；只有被打分的范围会离开本机。分数是 Jev 在四个级别上按概率加权给出的回答——无关、略有相关、相关（包含所问内容的一部分）、正中——映射到 0 到 1，所以四个级别分别落在 0、0.333、0.667 和 1。子代理并不被禁止使用它。
