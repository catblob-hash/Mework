`write` 用一次调用创建一个文件或整体替换其内容。模型在写新文件时用它，在重写规模大到打补丁只会添乱时也用它；`edit` 才是改动既有文件内部时更精细的工具。父目录按需创建。

## 审批

调用被归类为写入。在工作区、应用数据目录或一个已授予的额外目录之内，`request_approval` 每次都询问，`allow_edits` 和 `full_access` 允许。落在这些根之外的目标在 `allow_edits` 下也要询问；瞄准应用自身数据文档（应用数据目录中的 `document.v1.json`）的写入在这个级别仍然询问；应用数据目录下的 `memory/` 在任何级别都被拒绝，`full_access` 也不例外。**总是允许**的上限为你所回答卡片的风险级别。

## 行为与限制

内容最多 2 MiB 的 UTF-8，空字符串也是合法的文件。写入经过一个临时文件和一次原子替换，因此被打断的调用绝不会留下半个文件。`..`、符号链接和联接无法离开授权范围：边界在规范路径上检查，新文件则检查其最近的既有祖先。计划模式下，属于 Git 仓库内容的目标——已追踪，或 Git 不会忽略的新文件——会被拒绝，直到计划模式结束（见[计划模式](../working.html#plan-mode)）。既有目标必须先在本对话中读取过，而且当文件的修改时间比那次读取更新时写入会被拒绝，除非磁盘上的文本仍然是模型看到的那份。结果是一条简短的回执；工具卡以统一差异（unified diff）的形式展示这次改动，超过 64 KiB 后截断。事后阻断这次调用的 `PostToolUse` 钩子并不能撤销已经写下的字节：回执会说明它已运行，被拒绝的只是它的结果。
