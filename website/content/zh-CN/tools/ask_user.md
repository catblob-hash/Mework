`ask_user` 在输入框上方放一张选择题卡片并等你作答。当模型撞上一个不该替你选的岔路——两种方案取哪一种、三个文件里哪个才是对的、要不要带上一次迁移——它就会用它，每个选项都带一行短句，说明选择它意味着什么。调用会一直阻塞到你作答，你的回答就是这次调用本身的结果，模型在同一个回合里接着往下做。

## 审批

任何安全层级都不会询问，也不涉及批准卡：这个工具本身就是那个提问。它被归类为对话内的协调动作，只能由模型运行循环调度，绝不能手工执行。子代理永远拿不到它——需要决策的子代理改为向其父级回报。

## 行为与限制

卡片照 Claude Code 的 AskUserQuestion 设计。一次调用最多四个问题，每题两到四个选项、各占一个标签页；**其他**一行可以输入你自己的回答，标记为可多选的问题可以选多个。单选题选中一个选项就进入下一题；只有一道单选题的卡片，一选即交。多题的卡片最后是检查页，在那里提交已答的部分——没答的题可以留空。选项带预览时，这道题换成左右布局：右边是预览，下面是一行备注（按 `n`）。**先聊聊这个**会婉拒这些问题，交回你已经答了的部分，并请模型先和你把问题聊清楚。

有三种不作答的出口：

- **关闭卡片**——关闭按钮、`Esc`，或检查页上的取消——结果写的是你关闭了卡片，回合就此结束，不再向模型发请求。
- **卡片还在时从输入框发消息**，会先交回卡片上已填的内容（什么都没填就是你关闭了卡片），你的消息紧跟在这个结果后面，模型在同一个回合里一起读到。
- **停止运行**会连同运行一起撤下卡片。

回答按问题原文记在这次调用上，事后时间线里的卡片会显示它们。
