# Bundled model registry

This JSON is vendored verbatim from Cherry Studio's `@cherrystudio/provider-registry` package. During model discovery, it enriches bare upstream `GET /models` IDs into `ModelProfile` values with capabilities, context window, maximum output, and vendor data.

| 文件 | 上游路径 | 内容 |
| --- | --- | --- |
| `models.json` | `packages/provider-registry/data/models.json` | 911 条**规范**模型：能力、模态、上下文窗口、最大输出、family、ownedBy |

The upstream directory also contains `provider-models.json`, with 1,390 **provider-specific override rows** mapping `apiModelId → modelId`, plus provider-specific capability and limit changes. Do not restore it during synchronization unless providers first regain a stable vendor identity: its former key was `(built-in preset id, apiModelId)`, but provider IDs are now UUIDs and cannot match those rows.

## Resynchronize

```bash
curl -sSL -o cs.tar.gz https://codeload.github.com/CherryHQ/cherry-studio/tar.gz/refs/heads/main
tar -xzf cs.tar.gz cherry-studio-main/packages/provider-registry/data
cp cherry-studio-main/packages/provider-registry/data/models.json src-tauri/resources/model-registry/
```

After copying, normalize line endings to LF, update the commit and `version` values above, then run `npm run test:rust`. The `model_registry` catalog-invariant test verifies that the file parses and that its count and `version` agree with this README.

**Do not edit this file manually.** It is an upstream snapshot and local edits will be overwritten at the next synchronization. To change a model capability, update the mapping logic in [`src-tauri/src/model_registry.rs`](../../src/model_registry.rs), or let users change it in the model-properties drawer. User curation takes precedence over the registry; see `mergeModelProfiles`.
